# Игровая 3D-демка — промежуточная версия

## Запуск

```bash
cargo run --release --manifest-path apps/manonica-lab/Cargo.toml --bin manonica-game
```

`default-run = "manonica-lab"` сохраняет прежнюю команду запуска Lab.
Игровое окно использует тот же Meridian/WGPU, FIFO VSync и отдельный
поток рендера. Мир: 16 колонок 16×400×16, процедурный рельеф, арка,
ступени и кристаллы. Граница созданной области непроходима.

| Управление | Действие |
| --- | --- |
| WASD, мышь | Ходьба и обзор |
| Shift, Space | Бег, прыжок |
| ЛКМ | Собрать блок в инвентарь |
| ПКМ | Поставить блок / применить выбранный свиток |
| 1–6 | Камень, кристалл, трава, три свитка |
| Esc | Пауза и освобождение/захват курсора |
| R | Вернуться на точку появления |
| K / L | Сохранить / загрузить `saves/game.nbt` |

Коллизии персонажа, гравитация, прицел и взаимодействия реализованы в
`manonica-world`; рендер не владеет игровыми правилами. Снимок схемы v5
включает активные формульные программы и состояние поля. Файл сохраняется
через временный файл и переименование. Снимки v4 не мигрируются.

## Текущий этап

Сценарная контрольная точка сохранена коммитом `5a29bf1` для сравнения.
В актуальном коде встроенные типы воздействий заменены формульными
маноновыми программами из JSONL. Старые планы разрушения и импульсы
удалены. Добавлен [общий экспериментальный отклик материала](material-response.md):
отрыв при нагрузке, движение и установка после секунды покоя.
Добавлены пространственная температура, излучение и свет от нагрева,
временные частицы раздробленного материала и передемпфированный отклик
давления. Полный дымовой/газодинамический решатель ещё не реализован.
[Уравнения и ограничения](thermal-response.md).

Конструкции каста компилируются из графа формул по библиотеке
`circles.jsonl`; сгущения маны видны без фоновой засветки.
F3 показывает диагностическое поле. [Язык, трансляция и физические
ограничения](formula-spells.md).

Формат сохранения — v5, старые v4 не мигрируются. Проверки включают
сжатие/рассеивание, сохранение манонов, ограничение работы, энергобаланс,
восстановление программы, независимость от имени свитка, детерминизм
конструкций и изменение геометрии от коэффициентов.

Автоматический оконный тест:

```bash
cargo run --release --manifest-path apps/manonica-lab/Cargo.toml \
  --bin manonica-game -- --showcase --smoke-frames 900
```

Симметрия конструкций: [группы, орбиты, оси и ограничения](magic-circle-symmetry.md).

Воспроизводимый внеэкранный кадр (PPM):

```bash
cargo run --release --manifest-path apps/manonica-lab/Cargo.toml \
  --bin manonica-game -- --capture /tmp/explosion.ppm --at 0.8 --scroll 4
```

`--scroll 4/5/6` выбирает программу; `--at` задаёт время 0–10 с.

## Диагностика задержек

Игровой клиент поддерживает `MANONICA_FRAME_TRACE`, включая отдельные
`terrain_ms` и `effects_ms`. Для новой трассы требуется свободное имя файла:

```bash
MANONICA_FRAME_TRACE=game-frames.csv cargo run --release \
  --manifest-path apps/manonica-lab/Cargo.toml --bin manonica-game
python3 scripts/analyze_frame_trace.py game-frames.csv --warmup-seconds 0
```

Для короткого каста прогрев 10 с исключил бы само событие. `update_ms`
включает персонажа и связанный CPU-шаг; `draw_present_ms` включает ожидание
VSync. Независимый физический прогон той же игровой сцены:

```bash
cargo run --release --manifest-path apps/manonica-lab/Cargo.toml \
  --bin manonica-game -- --profile-physics --scroll 6 --at 6
```

Он выполняет 240 шагов по 1/40 с без окна и печатает p50/p95/max,
число тел и остаток энергии. Это CPU wall time, не GPU kernel time.
Геометрия кэшируется по колонкам и версиям соседей; загрузка другого
снимка полностью инвалидирует кэш. Контакты летящих тел ищутся только
в семи локальных клетках. Независимые от `n` формулы потока вычисляются
на гранях один раз на управляющий шаг; зависимые от `n` продолжают
вычисляться при каждом подшаге. Для независимого от концентрации потока число подшагов определяется
условием CFL с запасом 0.9 и пределом шага 0.0125 с. Проверяется
согласие с мелким шагом, сохранение манонов и энергетический баланс.
Это управляемая численная аппроксимация; отдельные траектории могут отличаться.

В текущем JSONL-вихре подъём и вращение используют одну огибающую с
разгоном 0.15 с. Радиальный профиль меняет знак вокруг параметра `radius`:
он выталкивает из оси и возвращает снаружи. Это управление маноновой
средой; тела получают движение только через общий обмен импульсом.
Тест проверяет раннее совместное движение и накопленный угол более π
на радиусе больше 0.8 м, помимо подъёма и энергетического баланса.

Физика игрового мира обновляется на 40 Гц, управление персонажем — на 120 Гц.
Между физическими шагами положение летящих тел кратковременно предсказывается
по текущему импульсу только для рендера, без изменения состояния решателя.
Для сравнения частот на одной программе профилировщик принимает
`--physics-hz 120` или `--physics-hz 40`.

[Измерения задержек вихря и ограничения аппроксимации](tornado-performance.md).
