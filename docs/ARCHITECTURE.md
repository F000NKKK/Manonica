# Архитектура Manonica

## Каноническая спецификация

Документ «Магическая инженерия — спецификация v0.1» определяет три состояния маны, переходы между ними, энергобаланс, магическую химию, материаловедение, биологию, пространственные конструкции и ТАУ. **Это спецификация мира, не инструкция сложить все модели в один крейт.**

Принцип: *возможности мира — следствие законов, а не предзаданных заклинаний*.

## Слои

| Слой | Крейт / каталог | Содержание |
| --- | --- | --- |
| Ошибки | `manonica-error` | `BaseError`, `ErrorCode`, `ClassifiedError` |
| Математическое ядро | `manonica-core` | `Quantity<U>`, единицы, векторы, матрицы, `Signal<U>`, `Evolution<S>` |
| Фундаментальная физика | `manonica-physics` | Свободный манон, движение, концентрация, поля, консервативные численные законы |
| Управление | `manonica-control` | П/И/Д, генераторы сигналов, пространство состояний, критерии Калмана |
| Исследования | `manonica-simulator` | Воспроизводимые эксперименты для калибровки гипотез |
| Материалы (позднее) | `manonica-materials` | Материальные решётки, ловушки связанных манонов, включая кристаллы |
| Химия (позднее) | `manonica-chemistry` | Реакции, материализация, трансмутация с балансами |
| Биология (позднее) | `manonica-biology` | Маносвязывающие ткани и регуляция |
| Адаптер мира | `adapters/minecraft/fabric/mc26_3` | Только первый игровой адаптер; без фундаментальных законов |

Направление зависимостей:

```text
manonica-error
      ↑
manonica-core
      ↑
manonica-physics ───┐
manonica-control ───┼──> manonica-simulator
                     └──> будущие материалы/химия/биология
                                    ↓
                              Minecraft adapter
```

Физика **не знает**, что такое `Crystal`, `Ore`, `BlockState`, манацит или конкретная руна.
Кристалл маны — высокоуровневый *материал* с решёткой и ловушками для связывания манонов, а не отдельный фундаментальный закон природы. Позднее `materials` будет задавать коэффициенты и геометрию ловушек, `chemistry` — скорости реакций, а `physics` — решать общие уравнения переноса и поля.

## Два масштаба вычислений

**Микро:** `ManonSystem` моделирует отдельные свободные маноны. На текущем этапе закон `FreeMotion` предполагает неизменную скорость и не моделирует превращения.

**Макро:** `FreeManaField` хранит концентрацию свободных манонов на 3D-сетке. `FreeDiffusion` — консервативная конечно-объёмная схема с закрытыми границами. Эта модель необходима для практической симуляции Minecraft.

Для кубической сетки с шагом `dx` и постоянной диффузией `D` используется явное приближение:

```text
n_i(t+dt) = n_i(t) + (D·dt/dx²) * Σ_{j∈neighbors(i)} [n_j(t) - n_i(t)]
```

Условие достаточной устойчивости в трёхмерном случае: `D·dt/dx² ≤ 1/6`.
Каждая внутренняя грань обрабатывается ровно один раз с противоположными приращениями у соседних ячеек. Никакая мана не возникает из-за внутренних потоков; нарушение численного баланса — ошибка вычислений, не «магическая нестабильность».

На этом этапе **не выполняются** конверсия манонов в энергию/материю, связывание, движение в потенциальном поле и силовое взаимодействие: их параметры и модель будут проверяться постепенно.

## ТАУ

`manonica-control` независим от `physics`. П/И/Д — самостоятельные типизированные блоки; сигналы — `Signal<Unit>` (ступень, синусоида, рампа, прямоугольный и одиночный импульс, ЛЧМ и др.). Модели линейных систем поддерживают критерии Калмана для наблюдаемости и управляемости.

**Внимание:** существующие `LinearSystem<X,U,Y>` предполагают одну размерность для всех компонент вектора состояния `X`. Полностью неоднородные состояния (например, положение + скорость) требуют дополнительного типизированного слоя и ещё не реализованы; текущий API не должен выдавать себя за универсальный решатель всех моделей ТАУ. Реализован также наблюдатель Луенбергера с коррекцией по инновации и типизированными матрицами. ЛАЧХ/ЛФЧХ, общие критерии устойчивости, неоднородные размерности состояний и оптимальное управление остаются следующими этапами.

## Игровые адаптеры

Ядро **не зависит** от Minecraft, версии игры или загрузчика. Первая интеграция — Minecraft Java Edition 26.3 / Fabric. Адаптер будет передавать снимки состояния и принимать пакеты изменений, не вызывая Rust на каждый блок.

CI должен запускать численные тесты, проверку размерностей и `clippy` для всей Rust workspace.
