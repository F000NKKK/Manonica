# Manonica Lab

Графическая лаборатория для воспроизводимых физических экспериментов.
Рендеринг через **Meridian SDK → WGPU**. Используются только публичные
экспорты `meridian-sdk`, без прямых импортов низкоуровневых крейтов движка.

## Запуск

```bash
cd apps/manonica-lab
cargo run --release
cargo run --release -- experiments/two_sources.toml
cargo test
```

Приложение находится в **отдельной Cargo workspace**, чтобы графические
драйверы, аудио и окружение Meridian не подключались к базовым тестам
численной физики `cargo test --workspace` из корня Manonica.

Используется **Meridian SDK версии 0.8.0** с временной привязкой
к Git-коммиту `49c68a1c8570e2d4ca6255169209508ccea686e4`.
Эта ревизия предоставляет FIFO VSync, асинхронное завершение окна через
`AppHandler::ready_to_close` и обновление динамических текстур на месте.
Опубликованный пакет SDK 0.8.0 пока не содержит этих API;
после отдельного исправляющего релиза можно вернуться к зависимости
на crates.io. Не требуется повторная публикация всего workspace.

VSync по умолчанию включён. Оконная система/WGPU управляет частотой
вывода на основе частоты обновления монитора. При необходимости можно
добавить программный предел: `MANONICA_RENDER_FPS=60 cargo run --release`.
Этот предел **не отключает** VSync и не ускоряет физический расчёт.

## Управление

| Клавиши | Действие |
|---|---|
| Ctrl+1 / Ctrl+2 / Ctrl+3 | Предустановки формул в редакторе |
| WASD + мышь | Полёт камеры |
| Escape | Захват / освобождение указателя |
| Space | Пауза / продолжение |
| R | Вернуть начальное распределение и время 0 |
| F | Включить / выключить декоративные вихри |
| Стрелки вверх/вниз | Порог отображаемой плотности |

## Устройство

- `experiment/` — TOML-схема, валидация, типизированный
  `ExperimentBuilder`, доменные ошибки
- `simulation/` — сохранение числа манонов, сборка поля из
  нормированных начальных распределений и вызов `FreeDiffusion`
- `visualization/` — геометрия окружностей и визуальное
  отображение реальной плотности из `FreeManaField`
- `app.rs` — жизненный цикл и камера Meridian SDK

`seeds` определяют **только начальное количество** свободных манонов:
каждая форма распределяет свой `total_manons` по сетке с нормировкой на
объём ячейки. Круги — пока **геометрические конструкции**, которые не
создают манонов и не меняют физические законы. Любые будущие связи
кругов с полями должны быть реализованы через общие законы
в `manonica-physics`, без знания типов высокоуровневых конструкций.

Декоративный эффект `wisps` тоже не влияет на симуляцию.
На данном этапе поле отображается полупрозрачными срезами объёма
с трёхлинейной интерполяцией и мягким визуальным затуханием на
границах расчётной сетки. Атлас готовится в отдельном потоке, без
индивидуальных объектов для каждой ячейки. Физические условия на
границе остаются непроницаемыми; визуальное затухание не меняет расчёт.
Полноценный 3D ray-marching требует отдельного прохода через SDK.

Для добавления своего эксперимента скопируй один из TOML-файлов
в `experiments/`. Параметры диффузии являются калибруемыми,
а не константами игрового мира.

## Физический backend

`--backend gpu` использует полный резидентный GPU-конвейер из
`manonica-compute-gpu`: перенос, потенциальный дрейф, материалы, тепло и
энергобаланс. `--backend cpu` использует общий эталон из
`manonica-simulation`; `auto` допускает резервный переход на CPU.

FIFO VSync задаёт кадровый ритм без дополнительного программного таймера
по умолчанию. `GPU BATCH` в F3 включает обмен и проверку снимка и показывает
число шагов. `RENDER WALL` включает ожидания GPU и представления кадра.
Численные замеры без окна выполняются через `manonica-simulator`;
подробнее — [compute backends](../../docs/compute-backends.md).

## Применение и завершение

Enter и Enter цифрового блока отправляют формулу на проверку в физический
worker. Редактор показывает `APPLYING`; геометрия и снимок состояния меняются
вместе только после подтверждения. При ошибке редактор остаётся открытым,
а прежняя симуляция продолжает работать. Пустые текстовые события не стирают
выделение после Ctrl+A.

При закрытии сначала останавливаются рабочие потоки, а цикл окна остаётся
живым до освобождения графических ресурсов. Подготовку CPU-потенциала можно
отменить между итерациями, в том числе при закрытии во время применения.

## Поиск кадровых пиков

Атлас поля, HUD и редактор переиспользуют выделения текстур. Графики F3
растеризуются фоновым потоком; поток рендера принимает готовое изображение.
Чтобы разделить задержки ввода, обновления атласа, оверлеев и отрисовки с
представлением, включите необязательную трассу сырых времён:

```bash
# From the repository root:
MANONICA_FRAME_TRACE=frames.csv cargo run --release --manifest-path apps/manonica-lab/Cargo.toml -- apps/manonica-lab/experiments/local_boundary_conductor.toml --backend gpu
```

Файл создаётся заново и должен отсутствовать; существующие файлы не
перезаписываются. Запись буферизована, без синхронного flush в каждом кадре.
Трасса не меняет сырые значения в F3 и не сглаживает реальный кадровый ритм.
Сравнивайте p50/p95 после прогрева на одном устройстве и с одинаковым окном.

Анализ сохранённой трассы с исключением первых 10 секунд прогрева:

```bash
python3 scripts/analyze_frame_trace.py frames.csv --warmup-seconds 10
```

Команда из корня проекта выводит p50/p95/max интервала кадра и каждой
кадровой стадии. `gpu_batch_ms` повторяет последнее наблюдение пакета;
считать эти строки независимыми GPU-пакетами нельзя. Для статистики
пакетов используйте `gpu-coupled`. Завершите Lab штатно перед анализом,
чтобы буфер трассы был записан на диск.

## Динамическая механика

Отдельный опыт двух гауссовых заряженных тел с динамическим полем:

```bash
cargo run --release --manifest-path apps/manonica-lab/Cargo.toml --   apps/manonica-lab/experiments/dynamic_mechanics.toml --backend gpu
```

`gpu` требует GPU-расчёт механики; `auto` пробует GPU и допускает CPU,
`cpu` использует f64-эталон. Графический рендер остаётся отдельным от
вычислительного backend. Полная механическая схема выполняется WGSL:
импульсы тел и мод, перенос тел, обновление амплитуд и второй полушаг.

Синие и оранжевые кольца — маркеры положений тел разных знаков заряда,
а не физический радиус объекта.
В периодической области маркеры переносятся на противоположную грань;
в F3 положения остаются развёрнутыми. Начальные скорости примерно
0.10 и 0.06 м/с, поэтому движение медленное.

В F3 показаны `MECH E`, `dE`, вектор `P` и максимальное `dP` относительно
начального состояния; энергия и импульс включают тела и динамическое поле.
Space ставит опыт на паузу, R восстанавливает тела, поле и начальные балансы.
Снимки GPU проверяются до применения; сброс и замена пересоздают устройство.

Конфигурация `[mechanics]` задаёт период, отсечение и список тел с массой,
положением, импульсом, зарядом и шириной. Механический опыт отделён от
концентраций, ловушек и квазистатического потенциала; их совместные законы
пока не определены. В Lab ограничены число тел и отсечение, чтобы шаг
и завершение оставались ограниченными по объёму работы.

Проверки GPU и жизненного цикла без окна:

```bash
cargo test --manifest-path apps/manonica-lab/Cargo.toml mechanical_gpu -- --ignored --nocapture
```

### Отображение динамического поля

В механическом опыте Tab переключает **потенциал → плотность энергии →
скрытие поля**. В редакторе формул Tab сохраняет прежнее действие.
Положительный потенциал голубой, отрицательный — оранжевый; энергия поля
показана золотистым цветом. Текущий канал и его единицы видны в F3.
Стрелки вверх/вниз меняют относительный порог отображения.

Локальная плотность энергии включает кинетическую, градиентную и
экранированную части динамического поля. Она не включает энергию тела
и взаимодействия; суммарная `MECH E` в F3 включает всю систему.
Цвет и прозрачность нормируются на пик текущего снимка, поэтому сами
цвета разных кадров не являются абсолютной шкалой энергии.

Снимок мод берётся из принятого CPU/GPU-состояния. Его значения на
ограниченной вспомогательной сетке и атлас срезов готовятся фоновым
CPU-потоком, не исполняющим физических шагов. Эта сетка служит только
отображению; её разрешение не меняет симуляцию. Очереди ограничены,
устаревшие каналы отбрасываются, подготовка сетки отменяется при закрытии.
Повторно используются текстуры и материалы; объём имеет размеры
периодической области. Это отображение срезами, пока без ray marching.
