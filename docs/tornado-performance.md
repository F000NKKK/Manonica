# Вихрь: аппроксимация и задержки игрового клиента

Изменения после `6479a36`:

- Поле и материал шагают совместно на 40 Гц, персонаж — на 120 Гц.
  Краткое предсказание положения тела сглаживает только отображение.
- Для потока без зависимости от концентрации `n` значения на гранях
  кэшируются на управляющий шаг. CFL определяет количество подшагов;
  максимальный подшаг 0.0125 с сохраняет необходимую точность. Для
  зависящих от `n` выражений сохранён мелкий шаг 0.005 с.
- Контакты динамических тел выбираются по семи локальным клеткам вместо
  полного перебора всех проб для каждого тела. Порядок обмена с конечными
  резервуарами сохранён.
- Геометрия кэшируется по колонкам и версиям соседей. Изменение блока
  пересобирает затронутые колонки, загрузка снимка инвалидирует кэш.
- JSONL-вихрь одновременно задаёт подъём, вращение и радиальный поток.
  Радиальная скорость меняет знак: нет постоянного схлопывания на ось.
  В языке по-прежнему нет команд объектам и именованных обработчиков эффектов.

## Оконный контроль RTX 4050

Два последовательных release-прогона на NVIDIA GeForce RTX 4050 Laptop GPU,
1280×800, FIFO VSync, по 900 кадров, три одновременных каста `--showcase`.
Первый уже содержит локальные контакты, кэш граней и колонок, но имеет
120 Гц взаимодействия с материалом и пять подшагов переноса.
Второй использует общий шаг 40 Гц и адаптивный перенос.
Прогрев не исключён: здесь важно сохранить короткие события самих кастов.

| Стадия | p95 до, мс | p95 после, мс |
| --- | ---: | ---: |
| Интервал кадра | 55.941 | 25.994 |
| Обновление мира/персонажа | 45.885 | 16.230 |
| Пересборка геометрии | 2.917 | 3.115 |
| Наблюдатель эффектов | 1.261 | 1.393 |
| Draw/present | 8.603 | 8.628 |

Тяжёлые задержки уменьшились, стабильные 144 Гц для трёх кастов ещё
не достигнуты. Это диагностическое сравнение, не строгий бенчмарк:
частоты GPU/CPU не фиксировались, траектории меняются при укрупнении шага,
максимальное число тел составило 848 и 720 соответственно. Начальный
кадр включает создание графических ресурсов: max frame 257.754/339.106 мс.
Оба прогона завершились без ошибок решателя. Конечные остатки связанного
энергетического учёта: 1.004e-7 и −1.385e-7 Дж.

## Отдельная физика одного вихря

Тот же executable, одна программа, 6 симуляционных секунд, без окна.
Здесь обе частоты уже используют оптимизированный перенос:

| Частота | Шагов | Всего CPU wall, мс | p50 шага, мс | p95 шага, мс | Пик тел |
| --- | ---: | ---: | ---: | ---: | ---: |
| 40 Гц | 240 | 1816.808 | 7.036 | 11.850 | 198 |
| 120 Гц | 720 | 1798.982 | 0.689 | 7.359 | 198 |

У поля собственный управляющий шаг 40 Гц, поэтому 120 Гц добавляет дешёвые
промежуточные шаги материала; меньший p50 не означает меньшую полную
стоимость. В этом замере полная стоимость близка: дальнейшая оптимизация
нужна прежде всего решателю поля. Нельзя выдавать уменьшение числа
контактных шагов втрое за ускорение всей физики втрое.

## Повторение

```bash
MANONICA_FRAME_TRACE=game-frames.csv cargo run --release \
  --manifest-path apps/manonica-lab/Cargo.toml --bin manonica-game \
  -- --showcase --smoke-frames 900
python3 scripts/analyze_frame_trace.py game-frames.csv --warmup-seconds 0
cargo run --release --manifest-path apps/manonica-lab/Cargo.toml \
  --bin manonica-game -- --profile-physics --scroll 6 --at 6 --physics-hz 40
```

Тесты проверяют ранний совместный подъём/вращение, орбитальную дугу больше
π на радиусе больше 0.8 м, сохранение манонов и энергобаланс. Сравнение
адаптивного переноса с мелким шагом ограничивает максимальную ошибку
плотности в отдельном гладком опыте; это не общая оценка ошибки всех
нелинейных программ. Возвращение в статику проверяется отдельно, включая
занятую клетку, поиск за локальным радиусом, полностью заполненный мир и
повторный поиск после освобождения места.
