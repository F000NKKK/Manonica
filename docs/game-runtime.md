# Игровой runtime мини-мира v0

`manonica-world` отделяет содержимое игры и состояние мира от Lab и
вычислительного backend. Основа начиналась как headless-демка мира: чанки, блоки,
предметы, сущности с координатами, инвентари, игровой счётчик времени и
сохранения. Добавлен [промежуточный 3D-клиент](playable-demo.md) с ходьбой, контактами
персонажа и сценарными свитками; чанковый GPU и физический язык заклинаний
остаются следующими этапами. Текущий `tick` выполняет эталонную диффузию
свободной маны на CPU; существующий GPU-путь Lab продолжает жить отдельно.

## Запуск

```bash
cargo run --release -p manonica-world --example mini_world
```

По умолчанию создаются две колонки 16×400×16 с разными плотностями,
игрок получает кристаллы и устанавливает блок, выполняются 30 тиков.
Затем мир кодируется в бинарный NBT и восстанавливается, проверяется
запас свободных манонов. `--save /tmp/manonica-demo.nbt` записывает
снимок в новый файл (существующий файл не перезаписывается).

```bash
cargo run --release -p manonica-world --example mini_world -- \
  --chunks 1000 --active 500 --steps 0
```

Вторая команда проверяет создание и сохранение целевой топологии с
однородно упакованными чанками. Она **не измеряет** расчёт 51,2 млн ячеек.
`--steps N` включает CPU-расчёт активной области; большой мир будет дорогим.
`--content assets/demo` задаёт каталог пакета содержимого.

## Реестры и структурированные данные

В `assets/demo` лежат `blocks.jsonl`, `items.jsonl`, `entities.jsonl`.
Одна строка — одно определение; пустые строки разрешены. JSON-комментарии
не поддерживаются. Неизвестные поля и дубли ключей ресурсов отклоняются.
Ключ имеет вид `namespace:path`, например `manonica:mana_crystal`.

Определения разделены на вложенные группы: `display`, `physics`,
`physics.mana`, `state`, `stack`, `behavior`, `inventory`, `metadata`.
Блок задаёт коллизионную форму, заменяемость, проницаемость для маны,
допустимые состояния и значения по умолчанию. Коллизионная форма пока
является данными для будущего контактного решателя. Предмет задаёт предел
стека и необязательную ссылку на устанавливаемый блок. Сущность задаёт
массу, коллайдер, размер инвентаря и метаданные; экземпляр отдельно хранит
`EntityTransform`, `Inventory` и NBT.

Реестр неизменяемый и проверяет ссылки перед запуском мира. Числовые
`BlockId`, `ItemId`, `EntityKindId` имеют разные типы и используются только
вместе с создавшим их реестром. В сохранения попадают именованные ключи.
Порядок строк пакета не влияет на идентификаторы и fingerprint.
Fingerprint — проверка совместимости содержимого, а не криптографическая
подпись. Изменение определений требует отдельной миграции сохранений.

В демо есть воздух, камень, кристалл маны, соответствующие предметы,
зонд, игрок и тестовое тело. Свойство `axis` кристалла допускает `x/y/z`.
Установка расходует один предмет только после успешной записи блока.
Разрушение сначала проверяет вместимость инвентаря, затем возвращает
предмет с NBT блока. NBT предмета переносится при повторной установке;
состояния блока вроде `axis` пока возвращаются к значениям по умолчанию.

## Чанки и перенос

`ChunkLayout` задаёт размеры и ширину ячейки, `ChunkCoord` — горизонтальную
координату, `CellPosition` — глобальную позицию блока. Отрицательные x/z
используют евклидово деление. Блоки хранятся палитрой состояний; однородные
индексы и плотности представлены одним значением. Блоковые NBT разрежены.
Статистика `payload_bytes` учитывает только массивы индексов/плотностей
или архивные байты, **не** RSS, палитры, NBT и служебные структуры.

Резидентность и активность независимы. `unload` переводит чанк в
неактивный бинарный архив в памяти; `reload` восстанавливает его. Это ещё
не дисковый streaming. Архивы входят в общий баланс манонов и сохраняются
в снимке вместе со статусом активности/резидентности.

Диффузия считает каждую грань один раз по старому состоянию и переносит
равные противоположные количества. Проницаемость грани — гармоническое
среднее двух блоков; камень непроницаем. Отсутствующая, архивная или
неактивная соседняя область имеет нулевой нормальный поток. Условие
устойчивости `D*dt/dx² <= 1/6`; невалидный шаг не меняет мир или часы.
Проверяется неотрицательность и общий баланс до принятия результата.
Эталон сравнивается с монолитным `FreeDiffusion` по всем ячейкам.

## NBT и границы формата

JSON-метаданные явно типизированы, например:

```json
{"capacity":{"type":"double","value":500.0},"owner":{"type":"string","value":""}}
```

Поддержаны все 12 типов полезной нагрузки NBT: числа, строка, три вида
массивов, однородный список и compound. Бинарный кодек —
[fastnbt 2.6.3](https://docs.rs/fastnbt/2.6.3/fastnbt/).
Снимок мира содержит версию, fingerprint реестра, layout, часы,
чанковые NBT-массивы и сущности с инвентарями. Это собственная схема
Manonica, не формат регионов Minecraft/Anvil и не обещание совместимости
с сохранениями игры.

До декодирования проверяются структура, длины, глубина, дубли ключей и
отсутствие хвостовых байтов. Лимиты: 64 MiB на сообщение, глубина 32,
2 млн элементов отдельной последовательности и бюджет узлов декодирования;
метаданные дополнительно ограничены 262144 элементами, списком 65536 и
строками 16000 байт UTF-8. Пакет JSONL — до 4 MiB на реестр и 64 KiB
на строку. Это пределы v0, а не формат хранения полного плотного мира:
для него нужны отдельные файлы/регионы и потоковая загрузка чанков.
Восстановление строит новый runtime; повреждённый снимок не изменяет
существующий мир. Политика будущих миграций пока не реализована.
