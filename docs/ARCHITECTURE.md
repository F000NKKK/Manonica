# Архитектура Manonica

## Независимость от Minecraft

Маноника не привязана к версии игры или загрузчику. Первая интеграция — Minecraft Java Edition 26.3 + Fabric, но это **только первый адаптер**.

- Rust `manonica-physics`: свободные/связанные маноны, поля, перенос, преобразования.
- Rust `manonica-control`: регуляторы и математическое управление.
- Rust `manonica-simulator`: отдельная лаборатория для проверки законов и подбора констант.
- Java `adapters/minecraft/fabric/mc26_3`: адаптация мира, событий, сохранений и рендеринга под конкретную платформу.

## Контракт будущего адаптера

1. Java формирует неизменяемый снимок области Minecraft с необходимыми физическими свойствами.
2. Rust пакетно получает снимок и рассчитывает шаг без знания Minecraft API.
3. Rust возвращает список изменений и данные поля, а не изменяет блоки напрямую.
4. Адаптер валидирует актуальность снимка и применяет изменения на безопасном потоке с бюджетом за тик.
5. Клиент рендерит уникальные математические 3D-конструкции по данным симуляции.

FFM/JNI-связь пока не реализована. Её контракт будем стабилизировать после работоспособного симулятора. Не допускается вызов FFI на каждый блок или манон.

## Инварианты первой модели

В первом эксперименте (кристалл + свободная мана) сохраняется **количество манонов**, так как превращения в материю и энергию ещё не реализованы. Полная модель будет проверять баланс энергии, импульса и массы с учётом каналов преобразования.

Для одномерной диффузии используются отражающие границы и явная схема с условием устойчивости `D * dt / dx² <= 0.5`.

Значения скорости захвата, освобождения, ёмкости и диффузии — экспериментальные настройки, не канонические константы.
